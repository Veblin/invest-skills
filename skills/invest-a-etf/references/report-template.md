**阶段划分（时间线）**：AI 按日期序列合成，如「1 月横盘 → 3 月低点 … → 6 月高点 … → 7-8 月回撤」。

### 事件-价格对照表（`--events`/缺省读 `events/{symbol}.json` 时必须有）

> 数据来自引擎 `events` 块（事件-价格 ±1 交易日对齐）。**两列拆分铁律**：
> 「同日事实」纯时间线罗列，不做因果断言；「可能关联（待验证）」按 confidence 分级——
> 一手来源事件可标「高可信说明候选（仍须交叉验证）」，二手一律「待验证」。
> 无事件文件 → 输出「无事件文件（events/{symbol}.json），对照表跳过」，不得自行编造事件。
> 有事件文件但引擎 `aligned` 为空（未传 `--history`/`--playbook`，或历史行情源不可用）→
> 「同日大波动」列写「未对齐（需 `report --history` 且历史行情可用）」，
> **不得由 AI 手工对齐或凭 K 线回忆补数**。

| 事件日期 | 事件（confidence 标注） | 同日大波动（引擎） | 可能关联（待验证） | 来源 |
|---------|------------------------|-------------------|-------------------|------|
| … | …（二手） | 2026-07-02 单日 -7.70% | 待验证：… | [来源](url) |
| … | …（一手） | … | 高可信说明候选：… | [来源](url) |

- 「同日事实」列禁止出现因果词（「因为/导致/由于」）；因果表述只允许出现在「可能关联（待验证）」列的模板化说明中
- 事件描述引用引擎 events 块原文，不二次改写（改述须保持事实边界：只缩略、不增删事实）

- 盘面结合（对照 invest-a-pulse `zt_industry_flow` 涨停热度）：同源行业（THS 与东财完全同名）直接对照 3/5/10 日资金流方向 vs 涨停家数前后半段；差异名（东财 Ⅱ 后缀/截断/军工四拆 vs THS 军工装备等）注明映射差异后定性对照；一致性/背离 → 值得展开的矛盾点（如「资金流入但涨停热度退潮」「资金流出但涨停热度升温」）

[证据强度: 引擎字段 ✅ 强（同花顺大单口径，跨源对照）；盘面结合为定性对照，弱于引擎字段]

> ⚠️ 口径：大单口径（同花顺行业资金流）；日间净额有噪声，方向/强度标签一律引用引擎字段
> （近端加速/减速为引擎输出，受量级守卫约束），不做引擎之外的强度断言；
> **趋势判断必须与日期（快照积累）配合**（trend_span_days ≠7 日须标注）——单时点数据是证据非信号，不得据此做方向性预测。
> 资金流仅作证据之一，与 §6 赛道 ETF 份额流、pulse 涨停热度三源对照后下判断。

|:---:|:---:|------|

- STEP 2 框架对照：盈利证据链 / 叙事前提 / 资金先行指标
- STEP 3 框架重估：未失效 / 需验证 / 已证伪 三态判定

### 合规与纪律规则（LAW / P0）

| 规则 | 含义 |
|------|------|
| LAW 6 | 合规红线：本备忘录**不提供买卖/仓位建议**；涉及参考价必须多情景 + 标注假设前提与概率权重 + 注明"仅供参考，不构成投资建议"；禁止无假设的单一目标价 |
| LAW 6a | 交易结构条款：允许基于情景的入场区间/失效触发/操作纪律等**交易结构分析**，但其性质是研究框架而非买入指令（区间≠建议） |
| P0 | 计算纪律：报告内一切数字必须由引擎字段或 Python 计算得出并标注来源，禁止任何形式的估算/心算 |

### 正文标记

| 标记 | 含义 |
|------|------|
| `[事实]` / `[分析]` | 事实陈述块（带来源）/ 逻辑推演块（带证据标签），研究报告的事实-分析分离格式 |
| `[证据强度: …]` | 四维证据标签：数据可靠性（✅/⚠️/❓）· 来源丰富度（🌐多源/📡单源/🔮推断）· 时效（🕐近/📅滞后/🗄️旧）· 交叉验证（✓✓/✓✗/—） |
| `[来源: 引擎字段名]` | 数字直接引用自数据引擎输出字段 |
| `[来源: Python calc: 公式]` | 数字由 Python 按公式独立计算（P0 纪律要求的两种合法来源标注） |

# ETF 研究备忘录模板（紧凑版）

> 研究工具，非决策工具。所有价格区间须标注假设前提；禁止买卖/仓位建议。

## 形态要求（2026-10-10 真实报告复检后收紧）

- **正文 = 首屏（结论三行 + 缺口表）＋ 3–5 个「有证据的自然主题块」**。标题自拟、顺序自定，
  一个主题块可覆盖多个研究职责；**目标正文约 2000–3000 中文字符**（附录单列，不计入）。
- **「研究职责映射」不是默认栏目、不是强制标题**：下表只用于**核对职责不被遗漏**；
  没有证据支撑的职责**不写成块**——合并进首屏缺口表，或写一句适用性说明，**不保留空章节**。
- **块与块之间不重复**同一读数/判断（首屏摘要引用正文不算重复；缺口表是缺口的唯一载体）。
- 以下内容统一放**附录**：数据底稿（字段映射/采集状态/复算口径）、复检与签认、术语字典；
  **工程枚举与精确字段路径只在附录**，正文一律读者用语（来源数字标签可保留字段映射指向）。
- 表格行的列数必须与表头一致——字面 `|`（如 `|涨跌|`）须写作 `\|`，否则渲染会静默丢列（机器 QC 按 error 拦截）。
- **排版**：[分析] 块结构化（列表/加粗/表格/引用），分析段落第一句=加粗主旨句（D4／原 LAW 17）——
  首屏或各主题块的分析句用「**结论：**」体例（lint 按该字面量检查）；
  首屏三行合计覆盖「数据 / 逻辑 / 分歧或不确定性 / 风险」四要素（至少一行给因果/条件连接词——
  「意味着/因此/若…则」；并写明一项分歧或不确定性来源，如「口径不一致，未对齐不作判断」）。
- **底稿保留与生产消费（单一代际）**：正文引用的每个数字必须来自**同代封存底稿**——引擎字段、
  `[来源: Python calc: formula]`、或本次已读一手源（URL + 定位）。同代 payload（`<ts>.payload.json`）
  在**写作前封存**（先 `report --payload-out`，再写作）；HTML 只读该 payload 渲染，**不重采**。
  **正式报告不得在封存后补采**；确需新数据 → 重新封存（新代）。字段表、序列、来源记录、公式与
  复算口径在「数据底稿」附录可见，不得以「摘要」名义删掉可复核数据。

## 研究职责映射（核对用；不是默认栏目）

> 左列是研究职责，中列是常见主题块写法（标题自拟），右列是适用条件与**无数据时的处置**。
> 只有**实际有证据**的职责才写成正文块；其余按右列合并或省略。

| 研究职责 | 主题块常见写法（示例，标题自拟） | 适用条件 / 无数据处置 |
|---|---|---|
| 身份与规模口径 | 「产品与规模口径」 | 必须核对（身份已核原文/待核）；口径三态（官方规模≠估算净值≠规模代理）不得互相冒充；无行情源时折溢价写不可得 |
| 持仓透视与暴露 | 「持仓与暴露结构」 | 有披露持仓即写（行业/主题必有）；仅前十大须标披露范围；**无数据 → 缺口表，不另起块** |
| 指数估值与适用性 | 「指数估值」 | 有 PE/分位即写（分位规则见下）；**无索引 PE / 无行业映射 → 一句话适用性说明**（并入本块或缺口表） |
| 估值框架与行业位置 | 可并入「指数估值」块 | 仅行业 ETF 展开（TMT 子组/全市场两档，不自行编组）；宽基 → 一句「不适用 + 依据」 |
| 跟踪质量 | 「实现质量与费用」 | 必核：净值/波动/MA/BOLL/RSI；TD/TE 仅两腿口径齐备时给，否则写停算并披露；费率未核写「版本费率已读、报告日未核」 |
| 历史演变 | 「净值路径回顾」 | 采集了历史行情才写；未采集一行说明，不编造 |
| 同类产品对比 | 「同类产品比较」 | 数据已随同代封存才写（宽基跨境用同指数产品）；**未执行/未映射 → 缺口表一行，不另起块** |
| 份额流与资金趋势 | 「份额与资金流」 | 有份额序列即写（窗口共同起止、实际覆盖照实标注） |
| 对冲与工具 | 「对冲与工具覆盖」 | 必核（静态映射待核线索）；期货基差映射可用时展开；未收录写「静态映射未收录对应期货品种（未核；不表示不存在/不可上市）」——**一行即可，不另起块** |
| 因子 / 主题逻辑 | 「主题逻辑（如适用）」 | 有可追溯来源才写；无来源则标「待验证」或省略 |
| 情景参考（可选） | 「情景与观察路径」 | 证据演化情景：无价位、无概率合法（不凑概率）；估值情景才需假设+概率+免责 |
| 情景预案（可选） | 「回撤档位与核查清单」 | 采集了预案才写；**百分比档位=触发核验深度，无 σ 倍数/统计概率解释** |
| 对抗性假设检验（可选） | 「关键前提与证伪条件」 | **只在报告实际存在可检验的分析假设时写**；纯历史事实/方法定义型报告**可以没有**——不得为凑栏目编造未来证伪条件；未核事实在缺口表，不包装成假设 |
| 「致命一击」（可选） | 可并入上述前提块末尾 | **只在报告承载方向性框架判断时写**；无方向性框架**直接省略**（不写「无方向性框架可归纳」占位、不制造方向性判断）；最弱环不得是「某数据未取得」 |
| 缺口与未核清单 | 「缺口与未核清单」 | 必写（首屏）；缺口/盲点/未知/观察日历的唯一载体（补证路径=数据/公告+时间节点+触发什么复核） |
| 背离核查 | 「背离核查」 | **仅当存在同对象、同期间的明确背离时写，否则整块省略**；禁止单日价格 vs 20 日份额拼矛盾；T+1 延迟只影响窗口末端最近少数交易日（因源/产品而异），不得解释整个窗口；并列 ≥2 候选解释+竞争解释 |

**分位使用规则（引用分位前逐项核对）**：分位必须伴随**历史序列/样本期间/指标定义/排名**；
中位数（或均值）是**展示上下文**，不是复算条件——某源没给中位数不等于分位不可算，不得写「无法复算分位」；
**不同源未对齐（口径/期间/定义不一致）→ 并列陈述，不判断「低位/高位」**；宽基 PE 是区间参考，不作择时信号。

**数值与标签的机器核验口径**（写数字时保持这些形态，机器会复算/对拍）：
- BOLL：正文写「上轨 X / 中轨 Y / 下轨 Z」三值同现，带宽行用标签「**BOLL 带宽** X%（=(上轨−下轨)/中轨）」；
- 净值位置行用标签「**NAV vs MA20 偏离**」「**NAV vs MA60 偏离**」（与引擎派生值一致）；
- 同类产品表头用「**{N}日资金流(亿) | 近5日(亿) | 份额变化%**」；份额块写明「**份额窗口**起止/数据行数」；
- 结论（首屏）三行每行带证据绑定（`[来源: …]`/`[证据: C]`/`[事实: F…]`）；「不可得/未核」也要给依据
  （如 `[来源: 数据状态记录]`）——该块在机器结论段证据扫描范围内，裸结论句会被拦。

## 合成侧检查（写完逐项过）

1. **正文只有首屏 + 3–5 个主题块、约 2000–3000 中文字符**？无空章节、无重复读数、无「未执行」独立成章？
2. **每个数字可追溯**（引擎字段 / Python calc 公式 / 一手源 URL+定位）；工程枚举与字段路径只在附录？
3. **缺口表**是缺口/盲点/未知/观察日历的唯一载体；未核事实未被包装成假设？
4. **分位**按分位使用规则；**背离**同对象同期间（不凑）；**假设检验**只列实际可检验前提（可以没有）；
   **致命一击**无方向性框架即省略；**预案**无 σ；**情景**证据演化不设价位/概率。
5. **首尾风险声明完整**；结论三行带证据绑定；表格列数与表头一致（字面 `|` 已转义）。
6. 机器准出：`uv run python skills/lib/report_qc.py <md> --fail-on error` 无 error 后方可进入人工三层复检。

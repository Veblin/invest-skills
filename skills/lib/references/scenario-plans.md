# 情景预案库（Scenario Plans）

> v0.2.6 新增。设计来源：`host-docs/v0.2.6/8.11直播量化指标体系深度调研_ABCD落地设计_20260812.md` §6。
> **定位**：参考值（科学计算）→ 情景预案（if-then 检查清单）→ 触发执行 → 复盘（journal）→ 命中率统计 → 修订预案库。
> **合规边界（LAW 6/6a）**：预案回答"到了 X，我检查什么、哪个假设被证伪"，**不回答"到了 X 就买/卖"**。触发 = 启动重新评估流程，动作由用户决定。预案为研究流程规则，非交易指令。

## 一、预案模板

```
预案 #{ID}：{标题}
├─ 触发条件（科学计算）: {点位/事件定义——全部来自引擎字段或 Python 计算，禁止 AI 心算}
├─ 触发基线（历史统计）: {触达后的历史行为统计 + 无条件基线对照（胜率/均值/样本量）}
├─ 预案检查清单（触发后启动，非交易指令）:
│   {1..4 项：检查什么、哪个假设被证伪、什么情况下参考位失效}
├─ 失效条件: {什么情况预案作废（防僵化）}
├─ 复盘字段: 触发日期 / 实际路径 / 判断对错 / 错在哪条 / 修订内容
└─ 版本: {日期 v{n}}
```

点位证据等级按 [report-conventions.md §2.4] 标注：L1 参考系 / L2 机制注记 / L3 习俗（可作触发但必须标注习俗）/ L4 反证（被引用时输出否定注记）。

## 四、闭环迭代机制

1. **触发即记录**：预案被触发 → 复盘字段必填（判断对错、错在哪条），写入 journal。
2. **季度聚合**：每季度统计各类预案的方向判断命中率 → 命中率 < 50% 的预案降级或修订参数（聚合必须 Python 计算，禁止目视计数）。
3. **版本化**：每次修订 = 新版本 + 修订理由（对应预注册"探索性变体"标注）。
4. **新预案只来自复盘**：复盘发现"没想到的场景"→ 补进预案库；预案库是复盘经验的结晶化。
5. **基线年检**：候选预案启用前须补基线；已激活预案每年重跑基线脚本校准（样本滚动更新）。

## 五、学术支撑（设计来源）

- 情景规划：Schoemaker (1995, *Sloan Management Review*)
- if-then 计划：Gollwitzer (1999, *American Psychologist*)；元分析 d≈0.65（Gollwitzer & Sheeran 2006）
- "提醒无效、预设触发有效"：Fischbacher et al. (2017, *RFS*)
- 复盘迭代 = 预测校准循环：Tetlock (2005) 狐狸型自我批判

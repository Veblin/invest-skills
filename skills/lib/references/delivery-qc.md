> **Canonical 源**：本文件由 9 个 skill 共用，随包携带（SkillHub `<pkg>/lib/references/`、WorkBuddy 与 release 包 `skills/lib/references/`），**不依赖仓库根指令文件**。

## 1. P0 数字铁律与引擎派生字段

**所有涉及数值的计算（加减乘除、百分比、均值、偏离度、比值、计数、推导等）必须由 Python 引擎或 Python 脚本完成。LLM 不得在脑中或对话中进行任何数学计算——心算、目视计数、脑内推导一律禁止，无论数字多简单。**

| 规则 | 说明 |
|------|------|
| **禁止 AI 心算** | 不得在报告/简报中写出任何经 AI 手动计算得出的数字（如 "NAV 低于 MA20 约 15%"）；**计数同样禁止目视**（N 个交易日、N 个净流出日等必须先跑 `len()`/聚合） |
| **清单二次加工必须 Python** | 引擎输出的清单（big_move_days 数组、份额流 rows、事件表等）**不是聚合**——从中数 N 个、算比例、做区间推导，必须跑 Python 聚合，禁止目视清单 |
| **极值断言须全量核验** | 断言"峰值/最大/最少/首个"前，必须对全量序列跑 Python 聚合（`max/min`），禁止凭打印的子集断言（实例：只看近 8 行份额流就断言"7/30 为峰值"，真实峰值是 7/20） |
| **引擎预计算** | 衍生指标（偏离度%、BOLL 位置%、日均波动等）由数据引擎统一输出到 `derived` 字段 |
| **报告引用** | 报告中所有数字必须直接引用引擎字段值或 `[来源: Python calc: formula]` 输出，禁止二次加工与心算推导 |
| **来源标注合法性（两种，无第三种）** | ① `[来源: 引擎字段名]` ② `[来源: Python calc: formula]`。"Python calc 视角"、"口径源自引擎"、"聚合验证"、"Python 复算一致"、"自洽校验"等**未实跑字样一律禁止**——要么真跑 Python，要么删除该数字；加工组数字（倍数/百分点差/占比等）须带公式标签（F2，见 `report-conventions.md` §2.3 强制 5） |
| **验证** | 涉及计算的数字若引擎未输出，先用 Python 算一遍，将结果作为引用源，再写入报告 |

**正确 vs 错误示例**：

```markdown
# ❌ 错误 — AI 心算
NAV 1.676 低于 MA20 1.9802 约 15.4%

# ✅ 正确 — 引用引擎 derived 字段
NAV 1.676 vs MA20 1.9802，偏离 -15.36% [来源: kline.derived.nav_vs_ma20_pct]
```

**引擎覆盖的衍生指标**（`query_etf_kline` → `derived`）：
- `nav_vs_ma20_pct` / `nav_vs_ma60_pct` / `nav_vs_boll_mid_pct` — NAV 与均线的偏离%
- `boll_position_pct` — NAV 在 BOLL 带内位置（0% = 下轨，100% = 上轨）
- `nav_to_boll_lower_pct` / `nav_to_boll_upper_pct` — NAV 距 BOLL 上下轨的%
- `boll_bandwidth_pct` — BOLL 带宽%（口径固定为 **(上轨−下轨)/中轨**；旧「除以下轨」口径已纠正，2026-10-10）
- `daily_volatility_pct` — 日均波动率（年化/√252）

**E1 板块同步性字段**（v0.2.7，collect 时随 kline.derived 输出；首跑须 `--force-sector-sync` 预热板块成分股缓存，冷缓存默认跳过并标注）：`sector_beta_60d` / `sector_r2_60d` / `idio_var_share` / `sector_dispersion` / `csad_gamma2` / `downside_corr_gap`（值域与中文标签见 report_qc）

**引擎未覆盖的计算**：先用 Python 脚本计算，将结果写入报告时标注 `[来源: Python calc: formula]`。

## 2. 第 0 层：机器准出（必跑，非可选自检）

```bash
uv run python skills/lib/report_qc.py <报告文件> --fail-on error
```

→ 无 error 级发现方可进入以下三层人工复检（退出码 **0=PASS / 1=WARN 均可交付**，**2=FAIL 不得交付**）；sourcing warning（F2 派生词缺来源 / F4 §N 引用不存在）逐条复核后消除或说明。qc 规则细节见 `skills/lib/report_qc.py` 层说明。

> **候选预检（`report … --preflight`）≠ 本步的替代**：`--preflight` 在临时目录执行**真实渲染**，再对候选产物跑 lint（claude 档）与完整 `report_qc`，退出码同为 0/2——用于**正式交付前的候选预检**（把 error 级 QC 前移，避免「渲染 → 改 → 再渲染」返工；标准链见 SKILL.md）。它**不是普通 `report` 自动强制执行的闸门**；最终路径仍须对本步命令（对最终落盘 md）跑 `report_qc` 与后续三层人工复检。

> **`--verify-data` 不是本步的加严开关，而是另一件事**：它会让 `report_qc.py` 重新联网跑 `collect_all` 做 audit/quality/rigor（仅个股），属**独立现场复核**。默认链（八分钟口径）只跑上面这条不带 `--verify-data` 的命令；要用它，明确当成另一次现场核验来对待，别混入默认链的耗时与成败判定。

> **机器 PASS ≠ 可交付**：第 0 层只拦可机械判定的问题，其后三层人工复检不可省。

> **产物哈希绑定与分层签认（`--record`）**：最终产物（md/html/payload/decision）齐备后，运行
> `uv run python skills/lib/report_qc.py <报告 md> --fail-on error --record --signoff <层>=<状态>[:备注]`
> 落盘 `<ts>.qc.json`：记录各产物**实际 sha256** + 本次机器结论 + 分层签认
> （`data_review` / `original_materials` / `manual_numbers` / `manual_compliance` / `manual_logic`）。
> 语义：**未执行层写 `not_executed`（≠通过）**，机器 PASS 与「URL 存在/摘要已读」都不能代替
> 原文核验与人工复检；此后修改任一产物一行 → 旧记录 `stale`、旧签认自动失效，须重跑 `--record` 重验。
> ETF 报告的同代消费（payload/记录/产物哈希）由 `report_qc` 的 `etf-generation` 层机器检查；
> 2026-10-10 增：BOLL 带宽按 `(upper−lower)/mid` 从原始值独立复算、同代派生数字对拍、
> 同类产品表期间/数值对拍、份额窗口对拍、排名与组内极值重算、已排除估值证据却在结论区称低位
> （反例与正控见 `test_b06_qc_record.py` 与 `test_report_qc.py`）。表列错位在 `structure` 层
> （ETF=error，其余类型=warning）。机器只拦可机械判定项，自由文本因果仍须人工三层复检。
> ETF 组内份额极值只在全组员都有可得数值、相同有效起止、明确 `confirmable=True`
> 时重算；缺成员/缺值/明确不可确认却无条件断言极值为 error，旧底稿缺确认字段为
> warning（不可视为通过）。混合正负值也须先过覆盖门，不因极值语义待人工而绕过。
> 份额极值重算只适用于份额变化/涨跌幅；总量、绝对份额及绝对单位变化留人工，
> 不套用 `share_change_pct`。否证只作用于同一分句，不能跨逗号保护后续断言。
> 五日资金流列须明确标识「资金流」；模板缩写「近5日(亿)」只在同表有明确资金流列
> 时核验，成交额/规模等其他指标不与 `flow_5d_e` 对拍。
> 采集日快照的份额披露日期未知，跨拆分窗口不得据采集日复权或给出确认流量。

> **`--verify-data` 的 `network_used` 语义**：只反映**实际发起**的联网层（stock collector）。
> 未执行联网时记 `false`——`--verify-data` 标志本身、URL 存在、缓存命中都不等于「已联网/已核原文」。

## 3. 第 1 层：数字复检（准确性）— 独立重算，非重新目视

> 复检者与写作者共享认知：**"重新看"无法发现目视/心算错误**。加工组数字必须重跑 Python，不依赖肉眼复核。

提取报告全部关键数字，按来源分两组：

| 来源分组 | 复核方法 |
|---------|---------|
| 引擎字段直引 | 对照原始 JSON 输出，值/单位/口径必须一致 |
| 加工组（%变化/计数/倍数/比例/区间推导） | **全部重跑 Python 复算**（`len()`/`max/min`/公式），对照标注的 formula |
| 检索/新闻口径 | 必须带「检索摘要口径，出处待核实」标注；**不得归因到未读原文的媒体** |

强制项：
- **财务语义**：按 [financial-semantics.md](financial-semantics.md) 检查对象/范围、流量/存量/比率/每股属性、累计/单季/TTM、币种/单位；增长和比值核对两端关系，不能以单个数值与快照一致代替。历史派生指标的来源必须是实际计算序列，不是当前可用的另一个来源。
- **计数断言（N 个/N 日/N 笔）→ 对引擎清单跑 `len()` 聚合**（R3，禁止目视清单）
- 极值断言（峰值/最大/最低/首个）→ 确认基于**全量序列**的 Python `max/min`
- 任何 `Python calc 视角` 类未实跑标注 → 删除该数字或重跑补标注
- 任何不匹配 → 修正报告后再进入第 2 层

**已知错误实例（不得重犯）**：① 子集断言（2026-08-07 只看近 8 行断言峰值，真实峰值在全量序列）；② 摘要归因（把 WebSearch 摘要数字归因到未读原文媒体）；③ 目视计数（2026-08-14 "8/4 起 6 日净流出"实为 7 日、"4-6 月 6 个上涨日"实为 5 个——引擎给的是清单，计数是 AI 目视的）；④ 未实跑标注（"Python calc 视角 -21%"实际没跑 Python）。

## 4. 第 2 层：合规复检（规则）

- **P0**：每个数字有引擎来源或 `[来源: Python calc: formula]`，无 AI 心算/目视计数痕迹（§1）
- **A1/A2（原 LAW 6/6a）**：无买卖/仓位建议；多情景带假设前提+概率权重；无无假设单一目标价
- **措辞规范**：`report-conventions.md` §3 禁止词替换表 + §3.2 已知违规模式 19 条逐一核对；[分析] 事实性前提带来源或「框架性陈述/待验证」标注、未被证据标签背书（§2.3 强制 7）；派生数字带 calc 公式、无「复算一致/自洽校验」类未实跑字样；正文 §N 交叉引用指向节含被引内容
- **宏观外推红线（E5）**：无"全线创新高"类整体断言；"距前高 X%"带口径（收益率/价格）+ 窗口起止；**传导链逐环节标注证据等级 A/B/C/D 且最弱环节（C/D 级）不得作核心论证（C9 强制检查项，lint 规则 `wording-macro-chain-evidence` 之外的人工复核）**；月频海外数据（英德法日 10Y 等）带「截至 YYYY-MM，滞后约 N 个月」staleness 标注
- **事实边界（`report-conventions.md` §2.3）**：无猜测/推断/幻觉；数据冲突并列不裁决；三态标注（可验证/公开不可独立验证/未知）
- **分析标记**：每个 [分析] 块带 SOP-EV 四维标签（`report-conventions.md` §5）
- **估值分位规则**：分位伴随中位数/均值（**中位数是展示上下文，不是复算条件**——不得因某源未附中位数写「无法复算分位」）；分位成立/复算的要素 = 历史序列 + 样本期间 + 指标定义 + 排名；**不同源未对齐不判断低位/高位**；亏损标的标注；仅模块 1 用"分位"一词（`report-conventions.md` §9.2）
- **估值口径与币种（C2-a）**：逐条核对各估值路径的币种/rf/来源标注（§9.3）；无「方向一致/共同指向」类表述；跨币种比较带两侧口径；含 PCR 的段落无「保费/期权价格/保护成本」措辞
- **期间与对象（C2-d）**：年度/半年/单季/TTM 不混比；行业家数与口径一致；未来事件不解释过去结果；二手材料不作核心论证（§9.4）
- **背离断言（C2-e）**：同对象、同期间、方向关系明确才可写「背离」；**单日价格 vs 20 日份额不构成矛盾**；T+1 延迟不得解释整个多日窗口（§9.4 第 7 条）
- **估值排除与结论（C2-f）**：报告已声明某估值证据不构成结论时，核心结论区不得再以无来源表述断言「低位/低估」类水平判断（§9.4 第 8 条）

## 5. 第 3 层：逻辑复检（自洽性）

- 核心判断与数据是否矛盾（如"资金承接"判断 vs 份额数据方向）
- 实际关键前提逐一检验且可证伪（不设固定条数）；**未核事实在缺口清单、未包装成「成立假设」**；证伪条件同对象同期间；「本代未取得的数据」未被写成最弱环；可公开取得的文件本次未读却被列为未来观察窗 → 不合格
- 致命一击为条件句（**无方向性框架时省略该栏目**，不写占位句、不制造方向性判断）；实际盲点/缺口逐条列出（不设固定条数，不得为空；ETF 并入首屏缺口表）
- 引擎标注「不可得/未知」的字段未被填充数字
- 事实引用存在不等于支持论述：历史分位、模型增长与历史 CAGR 的差额、多模型情景范围，均不能直接识别市场已计价的盈利预期；模型逆推须固定其他假设并实际求解。核心结论、方法边界、正文与底稿不得互相矛盾。
- **机器层能力边界（2026-10-10）**：机器 QC 只拦可机械判定项（表列错位、BOLL 复算、同代数字对拍、期间/极值排名、已排除估值证据偷入结论）。**自由文本因果判断、论证充分性与口径选择合理性仍须本三层人工复检**——机器 PASS 不豁免本层。

## 6. 复检顺序、汇报格式与失败处置

1. **顺序固定**：第 0 层 → 第 1 层 → 第 2 层 → 第 3 层，三层递进，逐层不通过即回到修稿，**不得跳层**。
2. **执行时点**：在**报告写入文件后、向用户发出简报前**执行。
3. **发现问题即修**：复检发现的问题**立即修正报告**，不得"带着已知问题发出、事后再改"。
4. **向用户汇报复检结果**：简报中说明复检结论与修正项/降级项，不隐去 WARN。
5. **失败处置**：第 0 层退出码 2（FAIL）→ 不得交付；三层中任一层不通过 → 修正后重跑该层；**无法修正的**按事实边界标注「未知/公开不可独立验证」，不得删除问题项以换取通过。
6. **阶段日志（2026-10-10）**：各阶段耗时按阶段分别记录（采集/写作/本复检/渲染签认），**含 LLM 写作与复检两个无法由 Python 计时的阶段**；常规 / 首次 / 源失败分开记载。引擎输出的秒数只证明采集/渲染段，**不能证明整体交付耗时**；关键证据缺口未补齐时，**超时也不得放行**（时长目标是目标，不是准出依据）。

## 7. 财务语义与反例回归

本节落实既有数字/逻辑复检及开发同类模式检查，**不新增每份报告都运行全套攻击的常驻步骤**。财务计算、评分、来源绑定、分析模板或 QC 改动时，在候选版本执行适用回归；单份报告交付仍须核查自身实际输入和完整产物，旧版本/旧侧车的通过不能替代。

| 反例 | 应失败的行为 | 应通过的正控 |
|---|---|---|
| BOLL 带宽口径（2026-10-10）：旧公式 `(upper/lower−1)` 或除以下轨 | 正文/底稿沿用 7.45（下轨分母）或以底稿自述值为真值 | 从原始 upper/mid/lower 按 `(upper−lower)/mid` 独立复算一致（159920 同数据 7.19）；缺值/零中轨停算不给数 |
| 表体行列数 ≠ 表头（未转义 `\|` 或漏格） | md/HTML 静默丢列；QC 放行 | 列数与表头一致（字面 `\|` 须转义）；ETF 报告机器层 error 拦截 |
| 组内极值/排名断言 | 零被过滤或各产品无共同窗口时仍机械判「组内最小」 | 零参与极值；共同 flow_window 起止齐备才判，缺共同窗拒绝比较并限缩表述 |
| 已排除估值证据 + 结论区低位断言 | 自述「摘要不构成结论」却在核心结论写无来源「估值低位」 | 结论区的估值水平判断带本次已读一手来源；或明写不判定水平 |
| Q1 与 H1 累计，累计上升但拆分 Q2 下降 | 直接比较累计行并输出单季环比上升 | 同期间单季重建及方向正确；缺 Q1 时停止单季计算 |
| 混期营收差 / CAPEX | 用新增季度营收获得研发/投资回报满分 | 指标窗口可比且代理含义明确，或声明不适用 |
| USD ERP 历史 + 独立 CNY 国债现值 | 保留 USD 值/分位却标成 CNY 来源 | 历史来源保持真实；若换基准则完整重算历史 |
| 半年 OCF/利润金额 + 另一个 TTM 比值 | 建立错误的对应关系 | 同期间金额与比值对应；TTM 单列来源/期间 |
| 正确分位或 CAGR 事实 + 未识别的市场解释 | 因事实 ID 真实便通过“已计价/低估”结论 | 位置事实、明确条件模型或待验证解释；无识别不裁决 |
| 多法情景范围 + 现价 | 唯一反推盈利假设或统一下移全部模型 | 仅位置描述，或固定单模型与其他参数实际求解 |

**证据记录**：保存修复前失败、修复后相同反例结果、合法正控、同类消费者检查和实际 MD/HTML/侧车；绑定源码（含未提交内容）、输入与产物身份。变更后重新签认受影响范围，不用测试数量或 `final` 名称证明完成。

**责任与实现边界**：实施者复现并自检；独立复检者按原要求另立检查清单，核验实际入口与完整结果。可机械判定的口径错误须进入计算/校验机制；证据能否支持自由文本归因仍须独立逻辑复检。当前新增规范并不表示检查器已有相应自动规则，未实现/未验证项明确列出。
